# 카카오 로그인 · 서버 저장 켜기 (Supabase)

웹 온맘은 지금 **게스트로만** 동작하고, 기록은 그 브라우저에만 남습니다.
이 문서대로 설정하면 **카카오로 로그인**할 수 있고, 로그인한 사람의 기록이 **서버(Supabase, 서울)**에 저장되어 휴대폰·PC 어디서 들어와도 이어집니다.

- 코드는 이미 들어가 있습니다. GitHub에 **값 두 개**(주소·공개 키)를 넣으면 다음 배포부터 켜지고, 빼면 다시 "준비 중"으로 돌아갑니다.
- 카카오 REST API 키와 client secret은 **Supabase 대시보드에만** 넣습니다. 웹(공개 저장소·브라우저)에는 들어가지 않습니다.
- 게스트는 지금과 똑같습니다. 서버로 아무것도 보내지 않습니다.

> ⚠️ **켜기 전에 맨 아래 "켜기 전 확인(개인정보)"을 먼저 끝내야 합니다.** 지금 온보딩 동의 문구는 "건강 정보는 내 기기에만 저장 (서버 계정 없음)"이라, 그대로 켜면 문구와 실제가 달라집니다.
>
> 웹은 이 "내 기기에만 저장" 동의만으로는 **서버에 아무것도 올리지 않습니다.** 카카오 사용자가 **서버 저장 동의**를 따로 해야(온보딩이 `acceptServerStorageConsent()`를 부름) 그때부터 올립니다. 온보딩에 그 동의가 들어가기 전에 켜면, 카카오 로그인은 되지만 기록은 그 브라우저에만 남습니다(서버 행이 생기지 않음).

---

## 1. Supabase 프로젝트 만들기

1. <https://supabase.com/dashboard> → **New project**
2. 이름: 예) `onmom-web`
3. **Region: Northeast Asia (Seoul) — `ap-northeast-2`** ← 꼭 서울
4. Database Password는 비밀번호 관리 도구에 보관합니다(웹에는 필요 없음).
5. 만들어지면 **Project Settings → General**의 Project ID(= project-ref)를 적어 둡니다.
   프로젝트 주소는 `https://<project-ref>.supabase.co` 입니다.

## 2. 표 만들기 (SQL 한 번 실행)

1. 왼쪽 **SQL Editor** → **New query**
2. 저장소의 `supabase/migrations/0001_user_states.sql` 내용을 **통째로** 붙여 넣고 **Run**
3. 확인: **Table Editor**에 `user_states` 표가 있고, 표 이름 옆에 **RLS enabled**가 보이면 됩니다.

이 SQL이 하는 일:

| 무엇 | 내용 |
|---|---|
| `user_states` 표 | 한 사람 = 한 행. 앱 상태 JSON 전체(프로필·산모수첩·증상 기록·기분 답·기록장), 형식 번호, 마지막 수정 시각 |
| 행 수준 보안(RLS) | **로그인한 본인 행만** 읽기·만들기·바꾸기·지우기. 공개 키만으로는 아무것도 못 봅니다 |
| 권한 | 로그인한 사용자(`authenticated`)에게만. 공개(`anon`)에는 없음 |
| 수정 시각 | 서버가 매깁니다. 두 기기가 동시에 저장해도 한쪽이 다른 쪽을 덮지 않게 웹이 이 값으로 확인합니다 |
| `delete_my_account()` | [계정 삭제] 때 본인 행과 로그인 계정을 함께 지웁니다. 로그인한 사용자만 부를 수 있습니다 |

## 3. 공개 키 확인

**Project Settings → API Keys**

- **Publishable key**(`sb_publishable_…`)를 씁니다. 예전 프로젝트라 **Legacy API keys**의 `anon` 키만 있으면 그것도 됩니다.
- **Secret key(`sb_secret_…`)·`service_role` 키는 절대 쓰지 않습니다.** 모든 사람의 건강 기록을 읽고 지울 수 있는 키입니다.
  실수로 넣으면 웹 빌드가 일부러 멈춥니다(그 키는 바로 폐기하세요).

## 4. 카카오 디벨로퍼스

<https://developers.kakao.com/console/app> — 메뉴 이름은 2026년 콘솔 기준이고, 바뀔 수 있습니다.

> **iOS 앱과 같은 카카오 앱을 쓰세요.** 카카오 회원번호는 앱마다 다르게 나옵니다. 같은 앱이어야 iOS와 웹의 계정 id(`kakao-<회원번호>`)가 같습니다.

1. **앱 선택**(없으면 [앱 만들기])
2. **웹 도메인 등록**: [앱] > [제품 링크 관리] > [웹 도메인]에 `https://5seoyoung.github.io`
   (예전 콘솔: [플랫폼] > [Web] > [사이트 도메인])
3. **카카오 로그인 켜기**: [카카오 로그인] > [사용 설정] > 상태 **ON**
4. **리다이렉트 URI**: [앱] > [플랫폼 키] > [REST API 키] > [카카오 로그인 리다이렉트 URI]에
   `https://<project-ref>.supabase.co/auth/v1/callback`
   ← GitHub Pages 주소가 **아닙니다**. 카카오는 Supabase로 돌려보내고, Supabase가 웹으로 돌려보냅니다.
5. **클라이언트 시크릿**: 같은 [REST API 키] 화면의 [클라이언트 시크릿]에서 코드를 만들고 **활성화**
6. **동의항목**: [카카오 로그인] > [동의항목]

   Supabase는 카카오에 **이메일(`account_email`)·닉네임(`profile_nickname`)·프로필 사진(`profile_image`)을 항상 함께 요청**합니다(끌 수 없음).
   세 항목이 모두 설정돼 있지 않으면 카카오가 **KOE205** 오류를 냅니다.

   | 항목 | 설정 | 웹에서 쓰는 곳 |
   |---|---|---|
   | 닉네임 `profile_nickname` | 선택 동의 | 화면 이름(안 주면 "카카오 사용자") |
   | 프로필 사진 `profile_image` | 선택 동의 | 쓰지 않음 |
   | 카카오계정(이메일) `account_email` | **선택 동의** | 쓰지 않음 |

   - 이메일 항목은 **비즈 앱**에서만 켤 수 있습니다. 사업자 번호가 없으면 [앱] > [일반] > [비즈니스 정보] > **[개인 개발자 비즈 앱]**으로 전환합니다.
   - 이메일을 **선택 동의**로 두고 다음 단계에서 **Allow users without an email**을 켜면, 사용자가 이메일 동의를 빼도 로그인됩니다.
   - 사용자가 동의한 닉네임·이메일·사진 주소는 Supabase 로그인 계정(`auth.users`)에 저장됩니다. 처리방침에 적어야 합니다(아래 체크리스트).

## 5. Supabase에 카카오 연결

**Authentication → Sign In / Providers**

1. **Kakao** → Enable
   - **REST API Key**: 카카오 [플랫폼 키]의 REST API 키
   - **Client Secret Code**: 4-5에서 만든 코드
   - **Allow users without an email**: **ON**
   - 이 화면에 보이는 **Callback URL**이 4-4에 넣은 주소와 같은지 확인
2. 같은 화면 위쪽의 **Allow new users to sign up**은 **ON** (첫 카카오 로그인 때 계정이 생깁니다)
3. **Email** 공급자는 **끕니다**. 웹은 쓰지 않고, 켜 두면 누구나 공개 키로 이메일 계정을 만들 수 있습니다.
   Anonymous sign-ins도 꺼져 있는지 확인합니다.

## 6. 돌아올 주소 등록

**Authentication → URL Configuration**

- **Site URL**: `https://5seoyoung.github.io/onmom_web/`
- **Redirect URLs**(Add URL로 둘 다):
  - `https://5seoyoung.github.io/onmom_web/auth/callback/`
  - `http://localhost:3000/auth/callback/` (내 컴퓨터에서 개발할 때)

끝의 `/`까지 똑같아야 합니다. 목록에 없으면 Supabase가 Site URL(서비스 소개 화면)로 보내 로그인이 끝나지 않습니다.

## 7. GitHub에 값 넣기(= 켜기)

저장소 **Settings → Secrets and variables → Actions → Variables** 탭 → **New repository variable**

| 이름 | 값 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 3의 Publishable key(또는 anon 키) |

- **Secrets가 아니라 Variables**에 넣습니다. 두 값은 원래 공개값이라(브라우저가 읽음) 숨길 필요가 없고, 배포 설정(`.github/workflows/deploy.yml`)이 `vars.`로 읽습니다.
- 넣은 뒤 **Actions → Deploy to GitHub Pages → Run workflow**(또는 main에 push)로 다시 배포하면 켜집니다.
- **끄기**: 두 값을 지우고 다시 배포 → 카카오 버튼이 "준비 중"으로 돌아갑니다. 이미 로그인해 있던 사람은 그 브라우저에서 기록을 그대로 쓰고, 서버에는 더 보내지 않습니다.

내 컴퓨터에서 확인할 때는 `.env.example`을 `.env.local`로 복사해 같은 두 값을 넣습니다(`.env.local`은 올라가지 않습니다).

## 8. 켠 뒤 확인

1. 휴대폰으로 `https://5seoyoung.github.io/onmom_web/login/` → [카카오로 시작하기] → 카카오 동의 → "로그인하고 있어요" → **온보딩**
2. 온보딩에서 **서버 저장 동의**를 하고 [온맘 시작하기]를 누르기 **전에는** 서버에 행이 생기지 않습니다(동의 전 전송 금지). 두 가지를 마친 직후 행이 하나 생깁니다.
3. PC 브라우저에서 같은 카카오 계정으로 로그인 → 온보딩 없이 **홈**, 휴대폰에서 쓴 기록이 보이면 성공
4. 행 확인은 Table Editor에서 **행 개수만** 봅니다. `state` 칸(건강 기록)을 열어 보지 않습니다(아래 관리자 접근 참고).

### 로그인·저장 동작 요약

| 상황 | 동작 |
|---|---|
| 처음 로그인 | 서버에서 먼저 읽고(읽기 전에는 절대 쓰지 않음), 행이 없으면 온보딩. **서버 저장 동의**와 온보딩을 마치면 그때 처음 저장 |
| 게스트로 쓰다가 카카오 로그인 | 그 브라우저의 게스트 기록이 이 카카오 계정으로 옮겨집니다(iOS와 같은 규칙). 공용 PC라면 다른 사람의 기록일 수 있으므로, **서버 저장 동의를 다시 받을 때까지** 서버에 올리지도, 서버 기록에 섞지도 않습니다(서버 기록을 읽어 보여 주는 것은 합니다). 게스트 때의 "내 기기에만 저장" 동의로는 올리지 않습니다 |
| 다른 기기에서 로그인 | 서버 기록과 그 기기 기록을 합칩니다 — 기록은 지우지 않고 모두 남기고, 프로필·산모수첩은 서버 쪽. 단, 그 브라우저에서 지난번 저장 뒤에 고치고 아직 못 올린 칸은 그 브라우저 값 |
| 쓰는 중 | 바뀌면 1.5초 모아 저장. 화면을 벗어나면(앱 전환·탭 닫기) 기다리지 않고 바로 저장해 봅니다. 두 기기가 동시에 저장하면 다시 읽고 합쳐서 저장. 실패하면 그 브라우저에 두고 잠시 뒤 다시 시도(다시 열어도 고친 값은 남음) |
| 열 때 인터넷이 끊겨 있었음 | 로그인을 확인하지 못하면 아무것도 바꾸지 않고, 인터넷이 돌아오거나 잠시 뒤 다시 확인해 저장을 이어 갑니다 |
| 로그아웃(설정 화면) | 남은 변경을 먼저 저장(최대 8초, 그동안 "로그아웃하고 있어요") → 로그아웃 → 공용 PC에 남지 않게 그 브라우저의 기록 사본 삭제. 저장이 안 됐거나 서버 저장 동의 전이라 기록이 그 브라우저에만 있으면 지우지 않고 "아직 서버에 저장되지 않은 기록이 있어요" 창 → [그래도 로그아웃]이면 기록을 그 브라우저에 남긴 채 로그아웃 |
| 계정 삭제(설정 화면) | 서버의 행·로그인 계정을 **먼저** 지우고, 성공했을 때만 브라우저를 비움. 실패하면 아무것도 지우지 않고 설정 화면에 이유를 알림(네트워크 실패 / 로그인이 끝남) |
| 세션 만료·다른 곳에서 로그아웃 | 기록은 그 브라우저에 두고 로그인 화면으로. 다시 로그인하면 이어서 저장 |

## 9. 문제 해결

| 증상 | 원인 · 해결 |
|---|---|
| 카카오 화면에 **KOE205** | 동의항목 3개(닉네임·프로필 사진·이메일) 중 설정 안 된 것이 있음 → 4-6 |
| 카카오 화면에 **KOE006** | 리다이렉트 URI가 다름 → 4-4에 `https://<project-ref>.supabase.co/auth/v1/callback` |
| 로그인 후 서비스 소개(`/onmom_web/`)로 와서 `?code=`만 붙어 있음 | 6의 Redirect URLs에 콜백 주소가 없음(끝 `/` 포함) |
| "카카오 응답을 처리하지 못했어요" | 로그인을 시작한 브라우저와 돌아온 브라우저가 다름(예: 카카오톡 인앱 브라우저 ↔ 기본 브라우저). 같은 브라우저에서 다시 시도. Supabase의 Kakao 설정(키·시크릿)도 확인 |
| "기록을 불러오지 못했어요" | 로그인은 됐지만 서버 표를 못 읽음 → 2의 SQL을 실행했는지, 프로젝트가 일시 중지되지 않았는지(무료 요금제는 오래 안 쓰면 멈출 수 있음) |
| 이메일 동의를 빼면 로그인 실패 | 5-1 **Allow users without an email** 켜기 |

## 10. 알려진 한계

- **카카오 "연결 끊기"는 하지 않습니다.** 계정 삭제는 온맘 서버의 기록과 로그인 계정을 지우지만, 카카오 쪽 앱 연결은 남습니다(카카오 Admin 키가 필요해 정적 사이트에서 못 함). 사용자는 카카오 계정 설정에서 끊을 수 있습니다.
- **iOS 앱은 아직 이 서버를 쓰지 않습니다.** 공유하려면 iOS가 같은 표·같은 JSON 형식(날짜 ISO 문자열 — DEV_NOTES §2 [#23])을 써야 합니다.
- 설정 화면의 로그아웃·계정 삭제는 2026-09-27에 `src/auth`(`useAccountSession` = `signOutEverywhere`·`deleteAccountEverywhere`)로 연결했습니다(`features/settings/SettingsScreen.tsx`, 판단은 `settingsView.ts performSignOut·performDeleteAccount`). Supabase가 없는 빌드는 지금까지처럼 브라우저에서만 처리합니다. 실제 Supabase로는 아직 한 번도 돌려보지 않았습니다 — 켠 뒤 8의 확인 때 로그아웃·계정 삭제도 확인합니다.

## 켜기 전 확인(개인정보) — 모두 체크한 뒤 7단계

건강 정보는 개인정보보호법상 **민감정보**입니다. 서버에 저장하는 순간 처리 방식이 바뀌므로 아래를 먼저 끝냅니다.

- [ ] **[필수 — 이것 없이 켜지 않음] 서버 저장 동의 받기(CPO 문구 + 온보딩 화면)** — 지금 문구 "건강 정보는 내 기기에만 저장 (서버 계정 없음)", 소제목 "건강 정보는 민감정보라 기기 밖으로 내보내지 않는 걸 원칙으로 해요."는 카카오 로그인 사용자에게 사실이 아니게 됩니다.
      카카오 로그인 시 서버(Supabase, 서울)에 저장된다는 내용의 **서버 저장 동의** 문구를 만들고, 게스트는 기기에만 저장된다는 점을 구분합니다. 민감정보 **별도 동의**로 받는지 확인합니다.
      - 온보딩(카카오 계정)이 이 동의를 받으면 `acceptServerStorageConsent()`(`src/auth`)를 부르게 연결합니다. 부르기 전에는 웹이 서버로 아무것도 보내지 않습니다.
      - 게스트 기록을 가져온 카카오 사용자(동기화 상태 `waitingConsent`, 온보딩 완료)에게 같은 동의를 다시 받는 화면이 필요합니다.
      - 서비스 소개(`/`)는 이 빌드에서 "카카오로 로그인하면 기록을 서버에 저장해, 여러 기기에서 이어 쓸 수 있어요."라고 말합니다(`features/landing/landingContent.ts`의 `whenKakaoLogin`). 이 동의 화면 없이 켜면 **이 문장이 사실이 아닙니다**(아무것도 올라가지 않음).
      - 웹은 서버 저장 동의의 **판**을 브라우저에 저장합니다(`SERVER_STORAGE_CONSENT_VERSION`, `src/store/sync/marks.ts`). 문구를 바꿀 때 판을 1 올리면, 이전 판에 동의한 브라우저는 새 행을 만들기 전에 다시 동의해야 합니다 [감사 #20].
        단, **이미 서버에 행이 있는 사용자는 그 행을 예전 동의로 보고 계속 저장합니다.** 문구가 바뀔 때 기존 사용자에게도 다시 받아야 하면(법률 검토) 행에 동의 판을 저장하는 작업을 추가로 요청해 주세요.

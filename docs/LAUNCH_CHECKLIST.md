# 온맘 웹 출시 체크리스트

사용자 관리(Supabase)·카카오 로그인·서버 저장·AI 상담을 **공개 사이트에서 켜기 전과 켠 뒤**에 할 일을 순서대로 적었습니다.
설정 방법 자체는 [`docs/SUPABASE_SETUP.md`](SUPABASE_SETUP.md)(아래에서 "설정 안내")에 있습니다.

- **단계 순서대로** 합니다. 한 단계의 칸이 모두 체크되기 전에는 다음 단계로 넘어가지 않습니다.
- 누가: **CPO** · **법률**(법률 자문) · **임상**(임상 자문) · **개발**
- 온맘은 의료기기가 아닙니다. 진단·점수·등급을 내지 않고, 판정은 정해진 규칙이 하며, AI는 판정 경로에 들어가지 않습니다. 아래 항목은 이 원칙이 켠 뒤에도 지켜지는지 보는 것입니다.

| 단계 | 사용자에게 보이나 | 끝나면 |
|---|---|---|
| 0. 준비 | 아니오 | 1~3을 검토할 수 있는 상태 |
| 1. 법·개인정보 | 아니오 | 동의·방침 확정 |
| 2. 운영 | 아니오 | 멈추지 않고, 백업되고, 이상을 알 수 있음 |
| 3. 제품·임상 | 아니오 | 문구·기준 확정 |
| 4. 켜기 | **예** | 게스트·카카오·서버 저장·지도·영상 공개 |
| 5. AI 상담 켜기 | **예** | AI 상담 공개 |
| 6. 켠 뒤 정기 점검 | — | — |

## 1. 법·개인정보 — 켜기 전 필수

건강 기록은 **민감정보**입니다. 이 단계 없이 설정 안내 C-3(사이트 Variables)을 넣지 않습니다.

- 검토용 요약과 법 조항별 체크리스트: [`docs/privacy/CONSENT_AND_POLICY_DRAFT.md`](privacy/CONSENT_AND_POLICY_DRAFT.md) — 1-1·1-2를 이 문서로 함께 봅니다.

- [ ] **1-1 서버 저장 동의 문구 승인** (CPO → 법률)
  - 파일: `src/features/onboarding/consentText.ts`(초안). 구조: 필수 (a) 개인정보 수집·이용 (b) 민감정보(건강정보) 처리 — (a)와 따로 (c) 만 14세 이상 확인, 안내 (d) AI 답변의 국외 이전(AI 기능을 처음 쓸 때 따로 받음).
  - 확인: 항목·목적·보유 기간·거부할 권리와 불이익이 빠짐없이 있는지, 게스트와 카카오 모두에게 맞는 말인지.
  - 승인 뒤 문구를 바꾸면 **개발**이 `src/domain/consent.ts`의 `CURRENT_CONSENT_VERSION`을 새 날짜로 바꿉니다(예전 판에 동의한 사람은 다시 동의할 때까지 서버에 올리지 않음).

  - 수집 항목에 카카오에서 받는 값(회원번호, 동의한 닉네임·이메일·프로필 사진 주소), 게스트 식별자, 건강 기록, 접속 기록이 모두 있는지.

- [ ] **1-3 처리 위탁·외부 업체 목록 확정** (CPO → 법률) — 방침 7절과 실제가 같은지

  - Anthropic(미국): 이전 항목(대화 내용(같은 대화의 최근 질문과 AI 답변, 최대 20개)·산후 주차·분만 방식·수유 여부, 약물 체크는 표에 없는 항목 이름), 국가, 시기·방법, 이전받는 자, 목적·보유 기간, 거부 방법과 효과. 5단계 전에 확정해도 되지만, 방침에는 켜기 전부터 적혀 있어야 합니다.

  - 설정 안내 A-7의 세 항목(닉네임·프로필 사진·이메일)은 Supabase가 늘 요청합니다. 쓰지 않는 사진·이메일도 받게 되므로 수집 최소화 관점에서 방침 문구와 카카오 **동의 목적** 문구를 맞춥니다.
- [ ] **1-6 관리자 접근 정책을 정하고 적어 둠** (CPO)
  - 관리자 화면(`/admin/`)은 집계와 계정 정보만 봅니다. 관리자 명단(`public.admins`)은 필요한 사람만, 이름과 이유를 기록합니다.
  - Supabase 조직 멤버·GitHub 협업자도 최소로. **Supabase 대시보드의 Table Editor·SQL Editor로는 모든 건강 기록을 볼 수 있습니다** — `user_states.state`를 열지 않는다, SQL은 개수·집계만 본다, 예외(사용자 요청 처리 등)는 기록을 남긴다를 규칙으로 둡니다.
  - 역할이 바뀌거나 떠나면 그날: 관리자 명단에서 삭제 · Supabase 조직에서 제거 · 그 사람이 만든 액세스 토큰 폐기 · GitHub 권한 회수.
- [ ] **1-7 보유·파기가 실제와 맞음** (CPO → 법률)

  - 게스트(익명) 계정을 얼마 동안 두는지(2-6)를 방침에 적습니다.
- [ ] **1-8 개인정보 보호책임자·문의처·유출 대응** (CPO → 법률)
  - 방침의 책임자·문의 이메일이 실제로 받는 주소인지.
  - 유출을 알았을 때 누가 무엇을 하는지(이용자 통지, 개인정보보호위원회·KISA 신고 — 민감정보는 규모와 관계없이 신고 대상인지와 기한을 법률이 확인), 연락 순서를 한 장으로.
- [ ] **1-9 의료기기 해당 여부 · 이용약관 · 면책** (법률)
  - 이용약관 화면이 필요하면 온보딩 동의 옆에 더합니다(개발).
- [ ] **1-10 동의 전 처리 확인** (법률)
  - [게스트로 시작]을 누를 때와, 켠 뒤 기존 이용자가 처음 방문할 때 **동의 화면보다 먼저** Supabase 익명 계정(계정 ID·가입/접속 시각·Auth 로그의 IP)이 만들어집니다. 기존 이용자는 예전(iOS와 같은) 안내 "기기 밖으로 내보내지 않는 걸 원칙으로"를 보고 쓰던 사람입니다.
  - 이 처리의 근거(예: 개인정보 보호법 제15조 제1항 제4호)와 처리방침·동의 문구의 표현을 확인합니다.
  - 승인되지 않으면 **개발**이 익명 로그인을 동의 뒤로 미룹니다(예전 브라우저 전용 게스트는 다시 동의한 뒤에 옮김). 4단계는 그 뒤에.

## 2. 운영 — 켜기 전

- [ ] **2-1 Supabase 유료(Pro) 전환** (CPO)
  - 무료 요금제는 **7일 동안 활동이 적으면 프로젝트가 일시 중지**되고(그동안 로그인·저장이 모두 실패), **자동 백업이 없습니다.** Pro는 일시 중지가 없고 매일 백업을 7일 보관합니다.
  - Organization → **Billing**에서 전환. 비용 상한(Spend Cap)은 켜 둔 채로 시작합니다.
- [ ] **2-2 백업 확인** (개발)
  - Pro 전환 다음 날 **Database → Backups**에 백업이 보이는지. 더 짧은 복구 시점이 필요하면(PITR) 비용과 함께 CPO가 결정.
- [ ] **2-3 계정 보안** (CPO)
  - Supabase 계정 **2단계 인증**(Account → Security), GitHub 2단계 인증, 관리자 카카오 계정 2단계 인증.
  - `SUPABASE_ACCESS_TOKEN`의 만료일을 달력에 적음.
  - **Network Restrictions**(DB 접속 IP 제한)를 켜려면 개발과 먼저 상의 — GitHub 워크플로(D-1)가 DB에 접속하지 못하게 됩니다.
- [ ] **2-4 모니터링** (개발 → CPO)
  - Supabase: Organization → **Usage**(사용량), 프로젝트 **Logs**(Auth·Edge Functions·Postgres). 함수 로그에는 상태·오류 종류·소요 시간만 남고 질문·답·건강 기록은 남지 않는지 한 번 확인.
  - GitHub: 워크플로 실패 알림을 받을 사람(Settings → Notifications → Actions).
  - Anthropic(5단계 뒤): 사용량과 월 한도.
  - 카카오: 지도·장소 검색 사용량(무료 한도).
  - 영상 서버: 잠들어 있으면 첫 요청이 1분 가까이 걸림 — 계속 그런지 주 1회 확인.
- [ ] **2-5 요청 한도와 비용 상한** (CPO)
  - 게스트 시작: 기본 IP당 시간당 30번(설정 안내 B-7). 사용자가 늘면 CAPTCHA(B-6)를 켠 뒤 올립니다.
  - AI 상담: `CHAT_HOURLY_LIMIT`(한 사람 시간당, 기본 30 — 처음 켤 때 10 권장)·`CHAT_GLOBAL_DAILY_LIMIT`(전체 하루, 기본 500) + Anthropic 월 한도.
  - CAPTCHA가 없으면 한 사람이 IP 하나로 시간당 게스트 계정 30개를 만들 수 있어, 한 시간 안에 AI 상담의 하루 전체 한도를 다 써 버릴 수 있습니다(그러면 24시간 동안 모두에게 AI 상담이 멈춤). AI 상담을 켜기 전에 CAPTCHA를 켭니다(5-0).
- [ ] **2-6 익명(게스트) 계정 정리 정책 결정** (CPO → 개발)
  - 게스트는 브라우저 데이터를 지우면 다시 들어올 수 없어, 주인이 없는 익명 계정이 쌓입니다.
  - 정할 것: 서버 기록이 없는 익명 계정을 며칠 뒤 지울지, 서버 기록이 있는 게스트를 마지막 접속 뒤 얼마 동안 둘지. 정하면 방침(1-7)에 적고 개발이 마이그레이션으로 자동 정리를 만듭니다. **대시보드에서 손으로 일괄 삭제하지 않습니다.**
- [ ] **2-7 건드리지 않을 설정** (모두)
  - Supabase **Project Settings → API Keys**의 **Secret keys** `default` 키를 지우거나 다시 만들지 않음 — AI 상담 함수가 씀. **Legacy API keys**(예전 `service_role`)는 chat 함수 Logs에 `"server_key":"secret_keys"`가 보인 뒤에만 끔(설정 안내 B-4).
  - 무료 요금제에서 일시 중지된 프로젝트를 **Restore**하면 예전 방식 키가 돌아오지 않습니다 — Restore 뒤 설정 안내 D-1을 다시 돌려 경고를 봅니다.
  - `supabase config push`를 실행하지 않음 — 대시보드의 인증 설정이 덮임.
  - 표·권한을 대시보드에서 손으로 고치지 않음 — `supabase/migrations`로만.
- [ ] **2-8 도메인을 바꿀 때 목록** (개발) — 한 번에 모두
  - 카카오 A-3 JavaScript SDK 도메인 · Supabase B-3 Site URL·Redirect URLs · GitHub Variable `ALLOWED_ORIGINS` → D-1 · Turnstile Hostname(B-6) · 처리방침의 사이트 주소
